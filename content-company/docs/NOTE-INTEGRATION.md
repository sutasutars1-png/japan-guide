# note 連携 & 自動再執筆

ロードマップ §22（note運用）・§30-31（公開/分析）・付録A #2（データ取得経路）・
§4（Reviewer 差し戻し）に対応。

## 方針（§22 に忠実）

> noteの操作については、公式に提供されている機能・連携方法を優先する。
> 非公式なブラウザ自動操作は最後の手段とする。（§22）

したがって本実装は **自動投稿しない**。公開は人間が note エディタに貼り付ける
前提で「貼るだけ」の Markdown を用意し、売上/PV は note 管理画面の **CSV** を
取り込む（付録A #2 が「実装上いちばん詰まりやすい」と指摘した経路）。

## 1. 公開用エクスポート（`NoteExporter`）

`python3 -m company note export <product_id>` / GUI「note出力」ボタン。

- `data/exports/<product_id>.md` に書き出す。
- 先頭にメタ情報コメント（タイトル・価格・カテゴリー・ハッシュタグ・商品ID）。
- 本文中の「―― ここから有料 ――」を
  `<!-- 👇 ここから下を note の有料エリアに設定 -->` に置換して境界を明示。
- 本文が既に H1 で始まる場合は見出しを重複させない。
- GUI ではエクスポート時に本文をクリップボードへコピー（貼り付けやすく）。

## 2. 実績 CSV 取り込み（`NoteImporter`）

`python3 -m company note import <csv> [--dry-run]` / GUI「note連携」の貼り付け欄。

- **列名のゆらぎを吸収**（日本語/英語）: タイトル/URL/ビュー/購入数/売上金額/スキ
  など。`¥` やカンマ入り数値もパースする。カンマ/タブ区切りを自動判定。
- **商品の紐付け**: ①URL 完全一致 → ②タイトル完全一致 → ③タイトル部分一致。
  公開時に保存した `product.url` があると最も確実。
- 一致した商品は `record_metrics` で PV/購入/売上/スキ を更新（note の累計値を
  そのまま反映）。`--dry-run` は更新せず対象だけ確認。
- 取り込み結果（一致/未一致/更新内容）を返し、Company Memory に記録。

取り込み後は `evaluate` / `report` / ダッシュボードがそのまま最新実績で回る。

## 3. 自動再執筆ループ（§4）

Writer は単独公開しない。Reviewer が `reject` したら、その**指摘（notes）を
feedback として Writer に返し、書き直す**。

- 上限は `Config.max_rewrites`（既定 **3回**）。0 でオフ。
- **実 LLM 生成時のみ**作動（雛形は書き直しても骨格のままで無意味なため、
  1回で差し戻し終了）。
- 上限まで通らなければ商品は `review` 状態で人間へ差し戻し、`failure` として
  Company Memory に記録。
- 各再執筆は `再執筆N: <title>` という Task として台帳に残る（§18）。

**コスト注意（§36-37）**: 1回の再執筆＝執筆+レビューで LLM 呼び出しが 2 回増える。
最大まで回ると 1 商品で最大 (2 + 2×4) = 10 タスク。`max_tasks_per_day` と併せて
調整する。
