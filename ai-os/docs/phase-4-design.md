# Phase 4 設計書 — LLMをループに入れる(Brain)

> ステータス: **設計のみ(未実装)**。実装前の手順書であり、将来の「環境コピー」商品ドキュメントの土台。
> ロードマップ §2.2 の作法に従い、着手前に設計を固定する。

## 0. 目的とスコープ

「ゴールを渡す → AIが計画し、コードを書き、サンドボックスで実行し、結果を報告する」ループ
(PLAN → EXECUTE → OBSERVE → ANALYZE → FIX → VERIFY → DONE)を実現する。

- **汎用**: 特定用途に縛らない。任意のゴールで成果物を作る仕組み。
- **組み替え耐性**: エージェントの並び(Flow)を自由に差し替えられる。
- **スキル管理**: 各エージェントの能力を再利用可能な形で管理する。
- **コスト**: 既定は無料(Gemini 無料API)。有料API・手動貼り付けも同じ仕組みで選べる。

非目標(後回し): ブラウザ自動操作(各社ToS/壊れやすさ/アカウントリスクのため)、分岐DAGの完全形。

---

## 1. 中核コンセプト:「APIのふり」をする単一インターフェース

Phase 0 で作った `LLMProvider` 境界を活かす。ループから見た呼び出しは常に:

```
answer = await provider.complete(prompt)   # API でも手動でも同じ1行
```

- **API プロバイダ**(Gemini 無料 / 有料Claude/GPT): HTTP で返す。
- **手動プロバイダ (`ManualPasteProvider`)**: プロンプトを UI に出し(自動コピー＋「開く」ボタン)、
  人が回答を貼り付けて「送信」を押すまで **async にブロック**し、その回答を戻り値として返す。

→ ループのコードは API と手動で**同一**。「APIを使っているかのよう」はコード上の事実になる。
手動貼り付けは、同じインターフェースの裏にある"遅い回線"にすぎない。

### 承認 = ハンドオフの引き金(人間を運び屋から承認者へ)

人間の「送信/承認」1クリックが同時に:
1. `ManualPasteProvider` のブロック解除 → 回答がループに返る(= APIコールが返る)。
2. 受け渡しを **監査ログに記録**(Phase 3 と接続)。
3. ループが**次エージェントのプロンプトを自動生成**(前段の成果物を差し込む)。

---

## 2. 3層の再利用オブジェクト(汎用・組み替えの土台)

概念を独立した3層に分離する。**Skill はライブラリ、Agent は Skill を参照、Flow は Agent を並べる。**

| 層 | 何か | 再利用単位 |
|---|---|---|
| **Skill** | やり方・知識・手順の名前付きの塊 | ライブラリ(使い回す資産) |
| **Agent** | 実行者(名前・プロバイダ・**権限**・**スキル**) | ノード(どのFlowでも使える) |
| **Flow** | Agent を並べた流れ(順序/ループ) | 差し替え自由な配線 |

これにより:
- 汎用 = Agent/Skill はゴールに中立。
- 組み替え = Flow を差し替えるだけ(Agent は不変)。
- 再利用 = 一度書いた Skill を複数 Agent/Flow で使い回す = **「環境コピー=商品」の中身**。

---

## 3. スキルモデル:主スキル(base)＋副スキル(overlay)

### 主スキル (base) — プリセット。複数切替・戻せる
- Agent の核となる能力・人格。**工場出荷プリセット**を持つ。
- **複数プリセットを切替可**(例: Builder に「Web開発」「データ分析」)。汎用・組み替えと相性が良い。
- 自由に編集できるが、**いつでも「プリセットに戻す」で復元**(実験で壊しても安全網)。
- 仕組み: プリセット(既定・不変) → 編集は作業コピーへ → 「戻す」でプリセットを作業コピーに再コピー。

### 副スキル (overlay) — その都度 追加/編集。使い捨て可
- 特定の仕事のために一時的に足す知識・手順。土台(base)を汚さない。
- **適用範囲を選べる**: `project`(そのプロジェクト常駐) / `run`(この1回だけ)。
  恒常的文脈は project、実験は run。

### 権限(capability)とスキル(skill)は別物
- **権限** = "してよいか"(shell実行してよい)。Phase 3 の Default Deny。**安全側**。
- **スキル** = "どうやるか"(良いレポートの書き方)。**知識側**。
- 画面でも分けて表示する。

## 4. ハンドオフ規約(システム所有の契約層)

自動連鎖のために、エージェントの出力は「成果物＋次は誰＋リスク」を含む必要がある。
**この書式規約はタスクスキルに書かない。** システム所有の別レイヤーに1つ置く。

理由:
1. **壊れない** — スキル編集で書式を消して連鎖が壊れるのを防ぐ。
2. **重複しない** — 全スキルに書式ボイラープレートをコピペしない。
3. **再利用** — タスクスキルは"中身"に集中でき、純粋に使い回せる。

### 1つの契約の両端(必ず一致)
| 端 | 役割 | 置き場所 |
|---|---|---|
| 出力側 | LLMに「この囲みで返せ」と指示 | プロンプト末尾に注入する規約層 |
| 解釈側 | 返信から【次へ】等を抽出 | AI-OS のパーサ |

→ **1つの「ハンドオフ規約」定義から両端を生成**する。ズレようがない。

### エンベロープ書式(人にやさしい区切り)
```
【成果物】
<成果物: 計画 / コード / レビュー文 など>

【次へ】<エージェント名 または DONE>
【リスク】<L0〜L4>
【メモ】<任意: 次への申し送り>
```

### パーサのフォールバック(書式が崩れても止めない)
- 【次へ】が無い → **Flow の既定の次**へ。
- 囲みが無い → **回答全体を成果物**とみなす。
- → 自動連鎖が書式ミスでハードに止まらない。

### ブックマークレットは"何も知らない運び屋"
- 役割は「ページ上の最新回答を**生テキストのまま** AI-OS に送り返す」だけ。
- 書式解釈は AI-OS のパーサが担当 → 規約が変わってもブックマークレットは更新不要。
- 既定は Gemini API のため、ブックマークレットは**Gemini以外を無料で使う手動エージェント専用**の任意強化。

---

## 5. プロンプト合成(最終形)

オーケストレータが実行時に組み立てる順序:

```
[Agent の役割]
  + [主スキル(base/選択中プリセット)]
  + [副スキル(overlay: project → run)]
  + [今回のゴール / 前段の成果物]
  + [ハンドオフ規約 ← システムが自動注入(末尾)]
        ↓
   provider.complete(...) へ
```

後の層が前を上書き/追記。手動貼り付けでも中身は同一(人に渡して貼ってもらうだけ)。

## 6. プロバイダ戦略

| プロバイダ | 種別 | コスト | 貼付 |
|---|---|---|---|
| **Gemini(無料API)** ← 既定 | API | 無料 | ゼロ・完全自動 |
| 手動貼り付け (`ManualPasteProvider`) | 手動 | 無料 | 貼付/1クリック |
| Claude / GPT(有料API) | API | 従量 | ゼロ |

- **既定は Gemini 無料API** で全エージェントを完全自動で回す。
- 「特定エージェントだけ Claude を無料で」→ そのエージェントだけ手動プロバイダに差し替え(同じ画面・裏の回線だけ変わる)。
- **エージェントごとに混在可**。UI は同一。
- 準備: Gemini API キー(Google AI Studio・無料)。Connections 画面で登録。キーは Secret Store でマスク(Phase 3)。

---

## 7. フロー(組み替え)と自動連鎖

- **Flow が既定の次を決める**(ユーザーが並べた順)。予測可能。
- Agent 出力の **【次へ】ラベルで上書き可**(自動連鎖):
  - 例: Reviewer が「テスト失敗 → 【次へ】Builder」でループ修正(OBSERVE→FIX→VERIFY)。
- **反復上限**(Flow 単位 `max_iterations`)で暴走防止。UI に「残り往復数」を表示。
- 実装段階: まず**線形の並び替え**(Phase 1 の Flow 画面のドラッグ)。後で**分岐/ループ(DAG)**へ拡張。

### 自動連鎖と安全の両立
「自動連鎖」= 人間が消えることではない。
- **推論の受け渡しは自動**で流れる。
- **危険な実行(L3/L4)だけ Phase 3 の承認モーダルで一時停止**。
- → 暴走しない。安全ゲートはそのまま効く。

## 8. データモデル素案(シリアライズ可能・書き出し前提)

将来ライブラリ化前提でデータ構造だけ用意し、実装は簡易から(境界を削らない原則)。

```jsonc
// Skill（ライブラリ）
{ "id": "skill_report", "name": "レポート作成", "kind": "task",
  "description": "いつ使うか", "content": "具体的な手順/知識", "version": 1 }

// Preset（主スキルの束・複数持てる）
{ "id": "preset_builder_web", "name": "Builder / Web開発", "role": "…",
  "skills": ["skill_code", "skill_test"], "capabilities": ["shell.execute", "filesystem.write"] }

// Agent（Preset を選び、副スキルを重ねる）
{ "id": "a_builder", "name": "Builder", "provider": "gemini",
  "active_preset": "preset_builder_web",
  "base_working_copy": { /* 編集中。プリセットに戻せる */ },
  "overlay_skills": [ { "skill_id": "skill_x", "scope": "project" } ],
  "capabilities": ["shell.execute", "filesystem.write"] }

// HandoffProtocol（システム所有・環境に1つ・原則触らない）
{ "id": "handoff_v1", "envelope": "【成果物】…【次へ】…【リスク】…",
  "inject_text": "回答は必ず次の囲みで返す: …",
  "parser": { "default_next": "flow", "fallback": "whole_as_deliverable" } }

// Flow（Agent を並べた配線・組み替え可）
{ "id": "flow_default", "name": "標準フロー", "max_iterations": 12,
  "stations": [
    { "agent": "a_planner",  "handoff_default": "a_builder" },
    { "agent": "a_builder",  "station_skills": ["skill_y"], "handoff_default": "a_reviewer" },
    { "agent": "a_reviewer", "handoff_default": "DONE" }
  ] }
```

すべて Template/Export(Phase 1 の画面)に含めて1ファイルで書き出し → 別PCで復元。
= **「私と同じ環境の作り方」という商品の実体**。

## 9. UX 素案(Execution 画面の"駅")

手動プロバイダのとき、各段はこう見える(API のときは自動で通過):

```
┌ Planner ───────────────────────── L1 ┐
│ 役割: ゴールを安全なタスク列に分解      │
│ ┌ 渡すプロンプト（自動コピー済）┐ [Geminiを開く][Claudeを開く] │
│ └────────────────────────────────┘                            │
│ ┌ 回答をここに貼る（Ctrl+V）────┐  ← ブックマークレットなら1クリックで自動投入 │
│ └────────────────────────────────┘                            │
│                      [ 承認して次へ → Builder ]               │
└──────────────────────────────────────────────────────────────┘
```

既存の承認モーダル＋WebSocket＋監査ログを流用できるため、配管の大半は既にある。
新規は「駅UI」「手動プロバイダの待受」「ハンドオフ規約の注入＋パーサ」「Gemini APIアダプタ」。

## 10. 実装ステージング(小さく始めて境界は残す)

1. **Gemini API アダプタ**(`LLMProvider` 実装)+ 単一エージェントで PLAN→EXECUTE→OBSERVE を1周。
2. **ハンドオフ規約層**(注入テキスト + パーサ + フォールバック)。
3. **Flow ランナー**(線形・`max_iterations`)+ 【次へ】上書き + 危険実行の承認停止。
4. **スキル**: まず Agent 直付けテキスト(主/副)+「プリセットに戻す」。データ構造はライブラリ前提。
5. **ManualPasteProvider** + 駅UI(手動運用の道)。
6. (任意) ブックマークレット、複数プリセット切替UI、Skill ライブラリ画面、DAG。

各ステージ完了時に `docs/phase-4-*.md` を Implementation/Tests/Security/Known/Next 形式で記録。

## 12. Definition of Done(Phase 4)

- ✅ 「このデータを分析して」等のゴール → AI がサンドボックス内でコードを実行し結果を報告。
- ✅ 反復上限・危険実行の承認停止が効く(暴走しない)。
- ✅ Flow を並べ替えると、その順で処理が流れる。
- ✅ 主スキルは「プリセットに戻す」で復元、副スキルは都度 追加/編集できる。
- ✅ 既定 Gemini 無料API で完全自動、手動貼り付けにも同一インターフェースで切替できる。
