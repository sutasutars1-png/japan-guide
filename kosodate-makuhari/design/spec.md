# 設計書：楽しさ版 子連れお出かけサイトへの改修（Claude Code 向け作業指示）

## 0. 目的
現在デプロイ済みの「検証済み設備が主役」のシンプル版を、**楽しさ（遊び・発見）が主役**の子連れお出かけサイトに改修し、Cloudflare Pages へ再デプロイする。
- **見た目の正**：`design/lp_mockup_reference.html`（このデザインを Astro で再現する）。
- **データの例**：`design/fun_spots_sample.json`。
- 参考の構造：いこーよ（カテゴリ／年齢別／目的別／季節／まとめ／詳細）。

## 1. 前提・制約
- リポジトリ＝この Astro + Cloudflare Pages プロジェクト。
- **コストゼロ厳守**（有料地図API不可）。AIは Gemini 無料枠のみ（既存 `functions/api/plan.js`）。
- 既存のデプロイ手順（`README.md` / `claude_code_handoff.md`）を踏襲。

## 2. コンセプト転換（最重要）
- **主役＝「楽しそうな行き先」**：遊園地/あそび場・体験、動物、科学館・学ぶ、公園、水あそび、美術・文化、観光。
- **授乳室・おむつ替え・トイレは"補足の小バッジ"に格下げ**（主役から降ろす）。
- **AIの役割＝楽しさの紹介文**（設備・料金・営業などの事実は断定しない）。

## 3. データ設計
- 取込は **`ingest/ingest_fun.py`** を使用（新規同梱済み）。OSM(tourism/leisure)＋千葉市OD を千葉市 bbox で取得・分類し **`data/spots.json`** を生成する。無料・鍵不要・LLM不使用。
- 各スポットのスキーマ：
  `{ id(slug), name, cat, lat, lng, amenities[], has_image, image_url?, intro }`
  - `cat`：あそび場・体験／動物とふれあう／学ぶ・科学館／公園でのびのび／水あそび／美術・文化／観光・名所
  - `intro`：カテゴリ別テンプレ（ゼロ円）。**任意で** Gemini により1件ずつ魅力文へ差し替え可（§7）。「AIによる紹介」と明記し、固有の事実は書かない。
  - `amenities`：赤ちゃんの駅OD／OSMタグから取れる範囲のみ（例「授乳室」「おむつ替え」）。**無くてよい（補足）**。
- 地域拡張は `ingest_fun.py` の `BBOX` を変更（同じパイプで千葉市→県へ）。

## 4. ページ設計（`design/lp_mockup_reference.html` を視覚の正とする）

### 4.1 デザイントークン（mockup と一致させる）
- パレット：`--ink:#2B2A33 / --coral:#FF7A59 / --coral-d:#F0603D / --teal:#22A6A0 / --sun:#FFC24B / --cream:#FFF7EF / --card:#fff / --line:#EFE7DD`
- フォント：見出し=Zen Maru Gothic(700)、本文=Zen Kaku Gothic New。
- 部品：カテゴリタイル（色地＋絵文字）、丸い年齢タブ、横スクロールのスポットカード、色サムネ、まとめ特集カード（グラデ）、リッチな法務フッター。

### 4.2 トップ `index.astro`
- **ヒーロー**：無料の遊園地写真を**外部URLで参照**（§5）＋暗いスクリム＋白見出し「今日は、どこであそぶ？」＋検索＋クイック（📍現在地・☔雨の日OK・🆓無料・👶0〜2歳）。右下に画像クレジット。
- **なにして遊ぶ？**：カテゴリタイル（§3のcat）。
- **年齢でえらぶ**：0〜6歳タブ＋横スクロールのスポットカード（実データ）。
- **いま注目**：おすすめ数件（人気データは無いので「編集おすすめ」等の中立表現）。
- **特集・まとめ**：まとめLPカード（§4.6）。
- **もうすぐのイベント**：将来枠（当面はダミー可、または非表示）。
- **フッター**：運営者情報/利用規約/プライバシー/免責/お問い合わせ＋出典（千葉市CC BY 4.0／OSM ODbL）＋トップ画像クレジット＋「一部はAIによる紹介」。

### 4.3 一覧 `spots/index.astro`
- **カテゴリ＋年齢＋雨の日(屋内)** で絞り込み（クライアントJS）。
- カードは**色タイル中心**（画像は一部のみ・`loading="lazy"`）。設備は**小バッジ**で補足。

### 4.4 詳細 `spots/[slug].astro`（SSG）
- **楽しさ紹介文（intro）を主役**に。
- 画像があれば Wikimedia サムネを1枚（幅指定・`loading="lazy"`）。無ければカテゴリ色ヘッダー。
- 「こんな子におすすめ」（年齢の目安）。
- **設備は小バッジ（補足）**。
- **schema.org**（`TouristAttraction` か `Place`）を JSON-LD で埋め込む。
- 近隣スポット（座標近接3件）への内部リンク。owner_claim 導線（店舗自己申告のみ）。

### 4.5 一日を組む `plan.astro`
- 「**楽しい半日/一日プラン**」に軸足。既存 `functions/api/plan.js`（Gemini）を流用し、候補＝楽しいスポット中心。昼寝・食事・設備は配慮として添える。

### 4.6 まとめLP（特集）
- 「雨の日でも遊べる屋内スポット」「0〜2歳と行けるおでかけ」「科学館・博物館めぐり」「千葉の水あそび」等を、データからフィルタして自動生成。**AIで本文を補える**（任意）。SEO/GEOの受け皿。

### 4.7 出典ポリシー `about.astro`
- 出典・鮮度（掲載日併記）・安全（開示のみ・非保証）・AI紹介の明記・投稿は店舗自己申告のみ、を説明。

## 5. 画像方針（重要・軽量化）
- **ヒーロー＝外部無料画像URLを参照**（base64は使わない。mockのbase64はプレビュー確認用のみ）。
  - 採用画像：東山動植物園 遊園地（コーヒーカップと観覧車）／作者 **Kyu3**／**CC BY-SA 4.0**。
  - URL例：`https://upload.wikimedia.org/wikipedia/commons/thumb/c/c7/%E6%9D%B1%E5%B1%B1%E5%8B%95%E6%A4%8D%E7%89%A9%E5%9C%92_06%EF%BC%9A%E9%81%8A%E5%9C%92%E5%9C%B0%EF%BC%88%E3%82%B3%E3%83%BC%E3%83%92%E3%83%BC%E3%82%AB%E3%83%83%E3%83%97%E3%81%A8%E8%A6%B3%E8%A6%A7%E8%BB%8A%EF%BC%89.jpg/960px-...jpg`（Commons API で最新の thumburl を取得して使用）。
  - クレジット表示必須（ヒーロー内＋フッター）。
- **一覧＝色タイル中心**（大多数のスポットは画像を持たない＝画像リクエストゼロ）。
- **詳細＝Wikimedia サムネがある一部のみ**、幅指定＋`loading="lazy"`。
- 1ページの表示は 20〜40 件でページ送り。

## 6. ガードレール（全ページ必須）
- 出典表示：千葉市（CC BY 4.0）／© OpenStreetMap contributors（ODbL）／画像は各ライセンス（例 CC BY-SA 4.0・作者名）。
- AI紹介文は「AIによる紹介」と明記。設備・安全は**補足・非保証・要確認**。
- 一般ユーザー投稿は不採用（**店舗自己申告のみ**）。
- **コストゼロ厳守**。

## 7. AI紹介文プロンプト（任意・Gemini）
- system：「あなたは子連れお出かけ紹介ライター。スポットの種別と名称から、親向けに40〜60字で『何が楽しいか・どんな子におすすめか』を書く。設備・料金・営業は断定しない。種別の一般的な魅力にとどめ、確認できない固有情報は書かない。」
- input：{名称／カテゴリ／エリア} → output：紹介文（AI生成と明記）。
- 差分のみ生成＋キャッシュでトークン節約。

## 8. 実装タスク（順序）
1. `design/lp_mockup_reference.html` を確認し、デザイントークン・部品を把握。
2. `ingest/ingest_fun.py` を実行し `data/spots.json` を生成（動作確認）。
3. デザイントークンを `public/global.css` に反映（mockと一致）。
4. `index.astro` を楽しさ版に差し替え（§4.2）。
5. `spots/index.astro`（§4.3）／`spots/[slug].astro`（§4.4）を差し替え。
6. まとめLP（§4.6）を最低2本、データ駆動で用意。
7. `plan.astro` を「楽しいプラン」に調整（§4.5）。
8. `about.astro` を更新（§4.7）。
9. `npm run dev` で全ページ確認 → `npm run build`。
10. Cloudflare Pages へ再デプロイ（既存手順）。要所で利用者に確認。

## 9. 完了条件（受け入れ基準）
- トップが**楽しさ版**（遊園地ヒーロー＋カテゴリ＋年齢＋まとめ）で表示される。
- 一覧が**カテゴリ／年齢／雨の日**で絞れ、設備は**小バッジ**。
- 詳細に**紹介文＋（あれば）画像＋schema.org＋設備小バッジ＋近隣**がある。
- 出典・画像クレジット・「AIによる紹介」表記がある。
- **無料のまま**動作し、Cloudflare で公開できている。
