## ゴール

BTC/USD を対象に、**人が手でパラメータを調整しなくても、システムが決められたルールで
自己改善し続ける売買bot** を作る。改善は必ず過去データでの再現(リプレイ)と実地の
ペーパートレードで検証し、根拠のない変更はしない。

## 開発の原則(変えるときはユーザーの明示的な合意が必要)

1. **実発注しない**: フェーズ6の判断基準を満たし、ユーザーが合意するまで、実資金の注文を出す
   コードパスを作らない。ペーパートレード(`paper/`)と実発注は別クラスとして分離する。
2. **パラメータはシステムが選ぶ**: 人が手で戦略パラメータを決めない。人が決めるのは
   「選び方のルール」(学習本数・再最適化間隔・昇格ゲート等)だけ。
3. **昇格は `decide()` のゲートを必ず通す**: 候補と現行を同じデータ・同じ検証区間で比較し、
   理由コードを記録する。実運用とリプレイで同じ判定ロジックを使う。
4. **先読み禁止**: どの判断も、その時点までに確定したデータだけで行う。
5. **変更は必ず比較で評価**: 戦略・ルールの変更は、リプレイで「自己改善 / 開始パラメータ固定 /
   バイ&ホールド」の3本と比較し、リターンだけでなく Sharpe・最大ドローダウンも見る。
6. **同じデータで選んで同じデータで褒めない**: 既定値や戦略の採否を決めたデータとは別の期間で確認する。
   最良の設定をそのまま採用しない(安定している領域を選ぶ)。
7. **足は1時間足を維持**: 履歴を延ばす目的で長い足に切り替えない(取引機会を減らさない)。
8. **データは積み上げる**: 保存データを上書きで失わない。出所(公式足 / 約定から再構成 等)を記録する。
9. **テストと記録**: `pytest` が通ること。検証結果は README に数値で残す(都合の悪い結果も残す)。

## フェーズ

状態: ⬜ 未着手 / 🔄 進行中 / ✅ 完了 / ⏸ 保留

### フェーズ1: 実運用前の修正 ⬜(目安 1〜2日)

- [ ] 未確定の足で判断しない: Kraken OHLC の最後の1本は形成中。`PaperTrader.step()` と
      ストア・リプレイが確定足だけを使うようにする
- [ ] `self-improve --csv`(デモモード)で学習データが再生位置より未来を含む問題を直す
- [ ] 新しい環境のセットアップ手順を1コマンド化(依存導入 → `seed_data` 取り込み → 差分 backfill → 起動)

**完了条件**: 上記がテスト付きで入り、リプレイと実運用の前提が一致している。

### フェーズ2: 24時間稼働 ⬜(目安 1週間)

- [ ] 稼働先を決める(VPS 推奨。予算・事業者はユーザーが決める)
- [ ] 常駐と自動再起動(systemd 等)
- [ ] データと判定ログを1日1回 GitHub にバックアップ(毎時コミットはしない)
- [ ] 死活監視: 2時間以上判断が記録されなければ通知。ログのローテーション

**完了条件**: PC の電源を切っていても稼働し続け、毎日のバックアップが届く。

### フェーズ3: 運用状況の見える化 ⬜(目安 1〜2週間)

- [ ] bot が日次の要約(仮想ポートフォリオ・判断・再最適化の判定)を書き出す
- [ ] ダッシュボードで「リプレイ」と「実運用」を並べて見られるようにする

**完了条件**: 実運用の成績とリプレイの成績を同じ画面で比較できる。

### フェーズ4: 検証を厚くする ⬜(作業 2〜4週間 + 実地観察 1〜3か月を並行)

- [ ] 履歴を1〜2年に延長(約定履歴は 2024-10 まで遡れることを確認済み)。下落・レンジ局面を含める
- [ ] 期間を分けた検証: 古い期間で選び方ルールを決め、新しい期間で確認する
- [ ] スリッページを含むコストモデル
- [ ] 実地のペーパートレード結果(フェーズ2以降)を唯一の本当の未来データとして評価

**完了条件**: 1年以上・複数局面のリプレイと、別期間での確認結果が README にある。

### フェーズ5: 戦略の拡張 ⬜(継続)

- [ ] 上昇相場で B&H に届かない弱点への対策候補を追加(トレンドフィルタ、ボラティリティに応じた
      保有比率、レンジ向け戦略など)。自己改善が戦略も選べるようにする
- [ ] 候補数に応じて昇格ゲートを厳しくする(候補を増やすほど偶然の当たりを拾いやすい)

**完了条件**: 追加した戦略がフェーズ4と同じ手順で、固定・B&H と比較されている。

### フェーズ6: 実資金運用の判断 ⏸(最短でも約3か月後。ユーザーの合意が前提)

判断基準(すべて満たすこと):
- [ ] ペーパートレード3か月以上、重大な運用トラブルなし
- [ ] 1年以上(下落局面を含む)のリプレイで、Sharpe と最大DDが B&H より良い
- [ ] 実地の成績がリプレイから大きく乖離していない

満たした場合の作業:
- [ ] 取引所選定(Kraken は 2023 年に日本居住者向けサービスを終了している見込み — 要確認。
      国内登録業者なら円建て銘柄で検証をやり直す)
- [ ] 実発注層を別クラスで実装。APIキーは取引のみ・出金不可
- [ ] 少額上限・日次損失上限・緊急停止
- [ ] 税務用の取引記録の自動保存(暗号資産の利益は雑所得)

## 既知の課題・メモ

- 他取引所(Coinbase, Bitstamp 等)は開発用クラウド環境のネットワーク許可リストで遮断。
  同一取引所で正確なため Kraken の約定履歴から再構成する方針
- 約定から再構成した足は公式足と価格が完全一致(48本で確認)。出来高は最大2%程度の差
- 設定次第でリプレイ結果の振れ幅が大きい(180日で +11.9%〜+25.8%)。単一の結果を過信しない
