## ゴール

BTC/USD を対象に、**人が手でパラメータを調整しなくても、システムが決められたルールで
自己改善し続ける売買bot** を作る。改善は必ず過去データでの再現(リプレイ)と実地の
ペーパートレードで検証し、根拠のない変更はしない。

## 開発の原則(変えるときはユーザーの明示的な合意が必要)

1. **実発注しない**: フェーズ6の判断基準を満たし、ユーザーが合意するまで、実資金の注文を出す
   コードパスを作らない。ペーパートレード(`paper/`)と実発注は別クラスとして分離する。
2. **パラメータはシステムが選ぶ**: 人が手で戦略パラメータを決めない。人が決めるのは
   「選び方のルール」(学習本数・再最適化間隔・昇格ゲート等)だけ。
3. **昇格は `decide()` のゲートを必ず通す**: 候補と現行を同じデータ・同じ検証区間で比較し、
   理由コードを記録する。実運用とリプレイで同じ判定ロジックを使う。
4. **先読み禁止**: どの判断も、その時点までに確定したデータだけで行う。
5. **変更は必ず比較で評価**: 戦略・ルールの変更は、リプレイで「自己改善 / 開始パラメータ固定 /
   バイ&ホールド」の3本と比較し、リターンだけでなく Sharpe・最大ドローダウンも見る。
6. **同じデータで選んで同じデータで褒めない**: 既定値や戦略の採否を決めたデータとは別の期間で確認する。
   最良の設定をそのまま採用しない(安定している領域を選ぶ)。
7. **足は1時間足を維持**: 履歴を延ばす目的で長い足に切り替えない(取引機会を減らさない)。
8. **データは積み上げる**: 保存データを上書きで失わない。出所(公式足 / 約定から再構成 等)を記録する。
9. **テストと記録**: `pytest` が通ること。検証結果は README に数値で残す(都合の悪い結果も残す)。

## 結論(2026-10-05、ユーザー判断)

**戦略探しはいったん終了する。** BTC/USD 1時間足の価格だけを使う売買ルールは、SMAクロス(買いのみ・買い/売り)、
多数決、損切り、momentum・trend_strength・shock_reversion の各種、現物の買いのみ、時間帯・曜日の偏りまで
試したが、2年分の `rolling`(選択に使っていない17か月)でどれも費用を上回る優位性を示さなかった。
実資金に進む根拠はない。データ(2年分)・検証の仕組み(replay / holdout / rolling)・ペーパートレード・
ダッシュボードは残し、新しい考えを同じ手順で検証できる状態を保つ。再開するときは下の「再開するなら」から。

## 再開するなら

- 新しい考えは必ず「1文で説明できる・調整値は2〜3個」に絞り、**合格基準を先に書いてから** `rolling` で検証する
  (既定: 2年分・60日×9期間。費用込みでプラス・B&H超え・過半数の期間でプラス)
- 価格だけの信号は多数試して不合格のため、再開するなら対象を変える(複数銘柄、価格以外の情報など)ことを検討する
- 手順: `bootstrap --days 730` → 戦略を `trading_bot/strategy/` に追加 → `rolling --strategy <name>` →
  README とこのファイルに結果を記録(不合格も残す)

## 既知の課題・メモ

- 他取引所(Coinbase, Bitstamp 等)は開発用クラウド環境のネットワーク許可リストで遮断。
  同一取引所で正確なため Kraken の約定履歴から再構成する方針
- 約定から再構成した足は公式足と価格が完全一致(48本で確認)。出来高は最大2%程度の差
- 設定次第でリプレイ結果の振れ幅が大きい(1年の確認期間で -0.4%〜+19.9%)。単一の結果を過信しない
- 選択期間では全設定が損失だったため、既定値 720/3/3 の選定根拠は「負けが小さく安定」にとどまる
- 買い/売りにしたことで下落局面でも利益を狙えるようになったが、選び方ルールによる振れ幅は依然大きい
  (選択期間 -22.9%〜+30.2%)。横ばいで上下に振られる局面は空売りでも損失になりうる
- 指値の約定は「次の足が突き抜けたら全量約定」とみなしている。約定しない注文は次の終値で出し直すため、
  急騰・急落時ほど約定が遅れる(この不利はモデルに含めている)
